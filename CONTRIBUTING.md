# Contributing to CareFlow HMS

We want to make contributing to CareFlow HMS as easy and transparent as possible.

## Pull Request Process

1. **Branch Naming**: 
   Use descriptive prefix names for your branches:
   - `feature/name-of-feature` for new attributes.
   - `bugfix/name-of-issue` for fixing errors.
   - `docs/name-of-doc` for writing documentation.

2. **Code Quality**:
   - Ensure all code conforms to the project linting configurations (`npm run lint`).
   - Run compilation checks (`npm run build`) before making PR requests.
   - Ensure typescript strict checks pass successfully without warnings.

3. **Submitting Changes**:
   - Open a pull request against the `main` branch.
   - Describe the changes made and link the relevant issue tags.
   - Wait for approval from the repository maintainers.

## Coding Style Rules

- Use CamelCase naming structures for standard JS/TS files.
- Use PascalCase naming structures for React layout components.
- Write explanatory code docstrings where applicable.
- Adhere to the DRY (Don't Repeat Yourself) guidelines.
